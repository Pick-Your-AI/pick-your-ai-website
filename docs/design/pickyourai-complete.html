01 / OUTCOMES

Four states. No hand-waving.

Compatibility is an evidence-backed claim, not a badge assigned to every combination. The live product should distinguish verified rules from missing data. This concept uses ten synthetic examples to demonstrate the v1 outcome and severity vocabulary. It does not interpret the frozen baseline ruleset or claim evaluator parity; the application retains its canonical evaluator.

✓ PASS · outcomeA rule is satisfied

The stated demo condition passes. This does not certify performance, deployment readiness or combinations the rule does not cover.

✕ FAIL · outcomeA condition fails

An applicable demo rule contradicts a selected fact. Its separate severity is error, warning or info; severity does not change fail into a different outcome.

? UNKNOWN · outcomeEligible evidence is missing

A rule applies, but its required eligible evidence is unavailable. Unknown is never presented as a pass.

— SKIPPED · outcomeIncomplete or not applicable

A missing pick is shown as Incomplete. False applicability is Not applicable. Both retain skipped and the rule's separate severity.

Severity is separate: error / warning / info. A combination with no demo rule is a coverage gap, listed outside the rule results, not an unknown or successful check.

02 / RULE ENGINE

Dependencies, not opinions.

Serving modes: api means provider-operated shared capacity. managed means dedicated or reserved capacity. Application hosting is distinct from model-serving capacity.

Each choice changes which downstream choices make sense. The examples below show the kind of reasoning users should be able to inspect instead of trusting a hidden score.

03 / COST & EVIDENCE

Show the math. Show the gaps.

Priced items and explicit exclusions

The fixed amounts are synthetic monthly scenario placeholders, not vendor quotes. Model APIs have synthetic per-million-token rates and require explicit monthly input and output counts. No workload means Unpriced; an explicitly entered zero is distinct from a blank. Unpriced selections stay outside the priced-item subtotal and are listed separately.

This demo accepts whole token counts from 0 to 1,000,000,000 per field and rounds the combined input/output charge half-up to cents once per model line, using integer arithmetic and no currency conversion. Real estimates also need eligible sourced rates, region, coverage and source dates; this concept supplies none of that qualification.

FREQUENT QUESTIONS

The important details.

Does the demo validate actual hardware or software compatibility?

No. The interactive checker demonstrates rule-based dependencies using a small illustrative dataset. Actual production support must be backed by independently verified evidence.

Are the model pricing and benchmark numbers live?

No. All prices shown in the mock are illustrative scenario amounts and not quotes. The preview contains no verified benchmark or real-time pricing feed.

Can I save my builds?

Yes, within this standalone HTML mock. Builds are saved in your browser using local storage, and you can export them as JSON for portability.

Can I use it without creating an account?

Yes. The mock does not require an account or transmit your configurations to a remote server. It runs locally in your browser.
